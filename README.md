# د معلوماتو نړۍ — WhatsApp Bot

دا بوټ د WhatsApp ګروپونو لپاره د پوښتنو ځوابولو، محلي معلوماتي زېرمې او انټرنېټي سرچینو لټون ملاتړ کوي.

## اوسنی حالت

د پوښتنو او ځوابونو برخه، د انټرنېټي سرچینو لټون او د سرچینو پر بنسټ د AI پښتو ځوابونه فعال دي. د ګروپ نظم ساتنه هم فعاله ده: کنځل او سپکاوی، چټک او تکراري سپم، د چینلونو او Status فارورډونه. **د نامجازو لینکونو اتومات بندیز فعال دی**؛ نامجاز لینکونه حذفېږي او اخطار ورکول کېږي. د بوټ د اجازې لېست لینکونه او د ګروپ تایید شوي مدیران مستثنا دي. د WhatsApp لایکونه/غبرګونونه د سپم شمېر یا اخطار سبب نه کېږي.

## نوي تنظیمات (Environment Variables)

- `ALLOWED_GROUPS` — د ګروپونو JID لېست سره په کاما جلا؛ که یې وتړئ، بوټ یوازې په همدې ګروپونو کې کار کوي. که تش وي، په ټولو ګروپونو کې کار کوي (پخوانی چلند). د ګروپ JID د ګروپ د لینک څخه یا د بوټ له لاګونو موندلی شئ.
- `ALLOWED_LINK_DOMAINS` — په کاما سره جلا د هغو ډومېنونو لېست چې لینکونه یې اجازه لري (لکه `example.com,bbc.com`).
- `ALLOWED_LINK_SENDERS` — د هغو WhatsApp شمېرو لېست چې د لینکونو شریکولو اجازه لري؛ په محرم Startup/Secrets کې یې تنظیم کړئ، یا که هلته خپل‌سري متغیرونه نشي زیاتېدای، د سرور په `private-runtime-config.json` فایل کې یې ولیکئ. د ګروپ تایید شوي مدیران هم مستثنا دي.
- `ENABLE_HISTORY_CLEANUP` — که `false` وي، د WhatsApp له همغږي شوي پخواني تاریخ څخه Status/چینل فارورډونه او نامجاز لینکونه نه حذفېږي.
- `WARNING_MUTE_ENABLED` — د درېیم اخطار وروسته د لنډمهاله محدودیت فعالول؛ ډیفالټ: `true`، د بندولو لپاره `false`.
- `WARNING_MUTE_DURATION_MINUTES` — د محدودیت موده په دقیقو کې؛ ډیفالټ: `120` (دوه ساعته)، اعظمي `1440` دقیقې.
- `RESET_WHATSAPP_SESSION`، `WHATSAPP_PHONE`، `OPENROUTER_API_KEY` — د اړتیا له مخې تنظیم کړئ؛ API key یوازې په SillyDev Startup/Secrets یا په سرور کې د `OPENROUTER_API_KEY` په محلي، ignored فایل کې وساتئ.
- `PRIVATE_QA_ALLOWED_NUMBERS` — د شخصي پوښتنو لپاره اجازه لرونکې شمېرې، د کامې په وسیله جلا او د هېواد له کوډ سره؛ واقعي ارزښتونه په SillyDev کې وساتئ، په GitHub کې یې مه لیکئ.
- `PRIVATE_QA_ALLOWED_LIDS` — اختیاري، دقیق WhatsApp LID پېژندونکي؛ د کامې په وسیله جلا، یوازې په محرم سرور تنظیماتو کې.
- `FULL_MODERATION_EXEMPT_PHONE_NUMBER` — اختیاري د مدیر/مالک د نظم له قواعدو د معافیت شمېره؛ که تنظیم نه وي، هېڅوک په دې ځانګړي استثنا نه معاف کېږي.
- `ENABLE_GROUP_QA`، `ENABLE_PRIVATE_QA`، `ENABLE_INTERNET_SEARCH`، `ENABLE_AI_SUMMARIZATION`، `ENABLE_LINK_MODERATION` — د اړوندو ځانګړنو د فعال/بندولو لپاره؛ ډیفالټ ارزښتونه `true` دي.
- `OPENROUTER_MODEL` — اختیاري؛ ډیفالټ: `openai/gpt-6-luna`.
- `AI_MAX_OUTPUT_TOKENS` — د AI د ځواب اعظمي اوږدوالی؛ ډیفالټ `1400` دی؛ له `500` تر `2000` پورې ارزښت منل کېږي. لوړ حد د اوږد ځواب امکان زیاتوي، خو دقت نه تضمینوي.

## ازموینې

`npm test` — د نظم ساتنې کړنې (کنځل، د لینکونو فعال بندیز، د لایکونو استثنا، تکرار او اخطارونه) په جلا توګه ازمویي؛ بوټ نه پیل کېږي.


## د کوډ جوړښت او د مسئولیتونو وېش

د بوټ کوډ په څو جلا برخو وېشل شوی، څو د یوې برخې بدلون د نورو برخو چلند بې‌دلیله بدل نه کړي:

- `index.js` — د WhatsApp پیغامونو عمومي بهیر، د بوټ پیل او د اتصال اداره.
- `lib/runtime-config.js` — د چاپېریال متغیرونه، د API کیلي لوستل، د AI حدود او د شخصي اجازه‌لیست تنظیمات.
- `lib/message-router.js` — د ګروپي، شخصي او نه‌منل کېدونکو WhatsApp پېژندونکو تشخیص.
- `lib/answer-engine.js` — د پوښتنې د ځواب پرېکړه، محلي معلومات، د سرچینو غوښتنه او وروستی fallback.
- `lib/research-engine.js` — د انټرنېټي لټون چمتو کوونکي، پایلو راټولول، د AI لنډیز او د سرچینو د لینکونو بڼه.
- `lib/health.js` — د HTTP روغتیا، د WhatsApp چمتووالی او د مهمو ځانګړنو د تنظیم حالت.
- `lib/moderation.js`، `lib/answer-plan.js`، `lib/search-relevance.js` او د سرچینو policy ماډولونه — د نظم، د پوښتنې د هدف، د پایلو د تړاو او د سرچینو د اعتبار خالصې کړنې.

د دې ماډولونو واحدي ازموینې په `npm test` سره چلېږي. د GitHub Actions په ازموینه کې د `index.js`، د ټولو `lib/*.js` ماډولونو او د ټولو `test/*.test.js` فایلونو د JavaScript نحو چک هم اجرا کېږي.

## د پوښتنو او ځوابونو سیستم

- د پوښتنې ډول پېژندل کېږي: تاریخ، جګړې، عملي لارښود، روغتیا، دین، ساینس، ټکنالوژي، تازه معلومات، ژباړه او عمومي پوښتنې.
- د «تفصیلي»، «مکمل»، «بشپړ» او ورته غوښتنو لپاره ځانګړې لارښوونې ورکول کېږي؛ تاریخي جګړې باید د نېټې، ځای، مقابل لوري، پایلې او اهمیت له مخې جلا تشریح شي.
- د سرچینو تړاو د پوښتنې له موضوع سره ارزول کېږي او د علمي/رسمي سرچینو لپاره د اعتبار امتیاز د برابر تړاو په صورت کې کارول کېږي.
- اوږده WhatsApp متنونه د پراګراف، جملې او کلمې په خوندي پولو وېشل کېږي؛ هره برخه د «برخه X/Y» نښه لري، څو د متن پای په خاموشۍ پرې نه شي.
- که د AI ځواب د ټوکن حد ته ورسېږي، بوټ یوازې یوه محدوده د دوام هڅه کوي او که بیا هم نیمګړی وي، دا محدودیت ښکاره کوي.
- د AI یا لټون د ناکامۍ په صورت کې بوټ نه تایید شوي حقایق نه جوړوي؛ د سرچینو اقتباسونه، موجود محلي معلومات یا د بیا هڅې روښانه لار ښيي.

د اړوندو برخو ازموینې په `npm test` سره اجرا کېږي؛ د دې ازموینو لپاره ژوندی WhatsApp اتصال ته اړتیا نشته.

## د محرمو تنظیماتو مهمه یادونه

د شخصي چټ د اجازه‌لیست او د مدیر د معافیت پېژندونکي نور د عامه سرچینې کوډ کې نه ساتل کېږي. له همدې امله، د پخواني چلند د دوام لپاره `PRIVATE_QA_ALLOWED_NUMBERS`، که اړتیا وي `PRIVATE_QA_ALLOWED_LIDS`، او `FULL_MODERATION_EXEMPT_PHONE_NUMBER` په SillyDev کې تنظیم کړئ. که د شخصي چټ اجازه‌لیست تش وي، بوټ شخصي معلوماتي پوښتنې ردوي؛ که د معافیت شمېره تشه وي، د چا د معافیت اټکل نه کوي. دا د خوندي ډیفالټ چلند برخه ده.

د `OPENROUTER_API_KEY` د سرور محلي فایل په `.gitignore` کې هم شامل دی. د API کیلي، WhatsApp pairing code، ناستې فایلونه او د شخصي پېژندونکو لېست په عامه کوډ یا لاګونو کې مه شریکوئ.

### که په SillyDev کې د خپل‌سري Environment Variables برخه نه وي

د سرور د **Files** برخې په اصلي فولډر کې دا محلي فایل جوړ کړئ:

`private-runtime-config.json`

د شکل نمونه یې په `private-runtime-config.example.json` کې ده. حقیقي ارزښتونه یوازې د SillyDev په محلي فایل کې ولیکئ؛ **نمونه فایل مه بدلوئ او حقیقي شمېره یا LID هېڅکله GitHub ته مه پورته کوئ.** د `.gitignore` له مخې اصلي `private-runtime-config.json` د Git له ثبت څخه خارج دی.

د اصلي فایل منځپانګه باید د څلورو تنظیماتو له نومونو سره JSON وي؛ د هر ارزښت پر ځای خپل مناسب مقدار ولیکئ:

```json
{
  "PRIVATE_QA_ALLOWED_NUMBERS": "",
  "FULL_MODERATION_EXEMPT_PHONE_NUMBER": "",
  "ALLOWED_LINK_SENDERS": "",
  "PRIVATE_QA_ALLOWED_LIDS": ""
}
```

شمېرې د هېواد له کوډ سره ولیکئ؛ څو شمېرې په کامه جلا کړئ. که LID ته اړتیا نه وي، تش یې پرېږدئ. که د Startup متغیر او د فایل ارزښت دواړه موجود وي، غیرتش Startup ارزښت لومړیتوب لري. د فایل له جوړولو یا بدلولو وروسته سرور Restart کړئ.

## د اتومات معلوماتي خپرولو سیستم

دا برخه هره ورځ د افغانستان په وخت **۰۸:۰۰، ۱۳:۰۰ او ۱۹:۰۰** کې د معلوماتي پوسټونو د خپرولو لپاره چمتو شوې ده. په لومړي پړاو کې شل له سرچینو سره برابر شوي پښتو پوسټونه کاروي، نو د اتومات پوسټونو لپاره د AI API یا تادیې اړتیا نه لري. د موضوعاتو څرخه علم، تاریخ، ټکنالوژي، روغتیا او عمومي معلومات پوښي.

**په ډیفالټ ډول اتومات خپرول بند دي.** ځکه د GitHub عامه فایلونو کې د هدف ګروپ JID نه ساتو، د سرور په Files/File Manager کې د پروژې په اصلي فولډر کې دا محلي فایل جوړ کړئ:

`auto-publisher-config.json`

د فایل بېلګه په `auto-publisher-config.example.json` کې شته. په اصلي فایل کې دا بڼه وکاروئ او خپل د ګروپ حقیقي JID ولیکئ:

```json
{
  "enabled": false,
  "groupJid": "PASTE_YOUR_REAL_GROUP_JID_HERE",
  "channelJid": ""
}
```

لومړی د ازموینې لپاره `enabled` په `false` پرېږدئ، د `groupJid` ارزښت وڅېړئ او سرور تازه کړئ. کله چې د هدف ګروپ او سرچینې متنونه تایید شي، `enabled` په `true` واړوئ. د بدلون د پلي کېدو لپاره سرور Restart کړئ؛ مهالوېش تنظیمات په هر ځل چک کې بیا لولي.

که په چاپېریال کې `AUTO_POST_ENABLED`، `AUTO_POST_GROUP_JID` یا `AUTO_POST_CHANNEL_JID` موجود وي، غیرتش چاپېریالي ارزښتونه د فایل ارزښتونو ته لومړیتوب لري. که `ALLOWED_GROUPS` تنظیم شوی وي، هدف ګروپ باید په هماغه لېست کې هم شامل وي. د ګروپ JID د `@g.us` په بڼه وي؛ د ګروپ نوم یا د بل چا شخصي چټ مه کاروئ.

د اتومات خپرولو حالت د `/health` په پایله کې د `autoPublishing` تر سرلیک لاندې ښکاري. په بریالي حالت کې `enabled: true` او `groupConfigured: true` باید څرګند وي. فایل کې د چینل JID اختیاري دی؛ د چینل خپرول تر جلا واقعي ازموینې مخکې تایید شوي نه ګڼل کېږي.

### د خپرولو حالت معلومول

د سرور `/health` پایله کې د `autoPublishing` څانګه د فعال/بند حالت، مهال‌وېش، او د هدفونو د تنظیم د وضعیت لنډ راپور ښيي. له فعالولو وروسته لومړی په ازمایښتي پړاو کې لاګونه او د ګروپ پیغامونه وګورئ.

## د انټرنېټي لټون سرچینې

بوټ د عادي پوښتنو لپاره په موازي ډول دا سرچینې لټوي:
- DuckDuckGo د ویب پاڼو د موندلو لپاره
- Wikipedia پښتو
- Wikipedia انګلیسي
- GDELT د تازه خبرونو او بدلېدونکو موضوعاتو لپاره

د سرچینو پایلې د سرلیک، لنډ اقتباس او اصلي لینک سره وړاندې کېږي. د خبرونو د تازه والي او د سرچینو د اعتبار لپاره اصلي لینک وګورئ.

## د مفصل پښتو ځوابونو فعالول

د سرچینو د پایلو پر بنسټ د مفصل، منظم او سرچینه‌محوره پښتو ځواب لپاره OpenRouter API کارول کېږي، که API key تنظیم وي. د OpenRouter حساب او API key جوړ کړئ، بیا د SillyDev د Environment Variables/Secrets برخه کې دا ارزښتونه تنظیم کړئ:

- `OPENROUTER_API_KEY` = ستاسې شخصي API key
- `OPENROUTER_MODEL` = `openai/gpt-6-luna` (اختیاري؛ که نه وي، همدا ډیفالټ دی)

**API key هېڅکله په GitHub فایلونو، عام پیغامونو یا سکرین‌شاټونو کې مه خپروئ.** د `openai/gpt-6-luna` کارول د OpenRouter د حساب/بیلینګ له شرایطو سره تړاو لري. که API key نه وي، اعتبار/بیلانس بسنه ونه کړي، یا AI ناکام شي، بوټ به د موندل شوو سرچینو سرلیکونه، لنډ اقتباسونه او لینکونه وښيي.

## فعالول او ازموینه

1. په SillyDev کې پروژه Restart یا Redeploy کړئ څو د GitHub تازه کوډ پورته شي.
2. په WhatsApp کې پوښتنه ولیکئ او د پیغام په پای کې حتمي `؟` یا `?` کېږدئ؛ د بې‌نښې پیغام لپاره بوټ ځواب یا ویب لټون نه پیلوي.
3. د بوټ د HTTP خدمت د `/health` مسیر وګورئ. د `webSearchProviders` ارزښت د لټون سرچینې ښيي؛ `aiSummarization: true` معنا لري چې د لنډیز API key تنظیم شوی دی.

## د WhatsApp ناستې ذخیره

د WhatsApp د ناستې معلومات د `session_auth_1/` فولډر په محلي فایلونو کې ساتل کېږي. بوټ باید د اصلي موبایل له بندېدو سره هم کار وکړي، خو د SillyDev سرور باید روان وي او د ناستې فایلونه باید پاتې شي. د WhatsApp د رسمي لارښود له مخې، که اصلي موبایل له ۱۴ ورځو زیات WhatsApp ونه کاروي، تړلي وسایل له حسابه وتلای شي؛ نو اصلي WhatsApp لږ تر لږه هر ۱۴ ورځې وکاروئ. د `/health` په ځواب کې `whatsapp.connection`، `whatsapp.authSessionSaved`، `whatsapp.lastDisconnectCode`، `whatsapp.reconnectScheduled` او `whatsapp.sessionResetRequested` وګورئ. که `connection` د `logged_out` حالت وښيي یا `authSessionSaved: false` وي، د WhatsApp په موبایل کې Linked Devices پرانیزئ او بوټ بیا ونښلوئ. که `sessionResetRequested: true` وي، د نوي اتصال له بشپړېدو وروسته په SillyDev Environment کې `RESET_WHATSAPP_SESSION` لرې کړئ یا `false` کړئ.

## مهم محدودیتونه

- ویب لټون تل بشپړې یا بې‌خطا پایلې نه ورکوي.
- کله چې د AI API key نه وي، بوټ د سرچینو اقتباسونه ښکاره کوي، خو د هغوی بشپړ متن په خپلواکه توګه نه شي ترکیبولای.
- د خبرونو، روغتیا، قانون، پیسو او نورو حساسو موضوعاتو په اړه اصلي او باوري سرچینې په خپله هم وګورئ.
- د WhatsApp عادي ګډونوال د WhatsApp په اصلي سیستم کې په انفرادي ډول نه شي mute کېدای؛ له درېیم اخطار وروسته بوټ د تنظیم شوې مودې په اوږدو کې د هماغه غړي راتلونکي پیغامونه حذف کوي. بوټ باید د ګروپ مدیر وي؛ د بندیز حالت په موقتي حافظه کې دی او د سرور له بیاچالانېدو سره پاکېدای شي.
